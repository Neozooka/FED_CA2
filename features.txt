HTML FEATURES (Relevant to HTML Coding Criteria)
--------------------------------------------------------------------------------

SEMANTIC STRUCTURE
  - <header>, <nav>, <footer> are generated once inside javascript/header-footer.js
    and injected into every page via JavaScript, so the semantic markup is
    identical and consistent across all 12 pages instead of being copy-pasted.
  - <section> and <article> elements are used to break up page content
    (e.g. hero, features, FAQ, comparison sections).
  - <main>-equivalent wrapper divs hold each page's unique content between the
    shared header and footer.

NAVIGATION
  - Shared responsive nav bar (desktop menu bar + collapsible mobile hamburger
    drawer) appears identically on all 12 pages via header-footer.js.
  - A persistent cart badge and back-to-top button are part of the same shared
    component.
  - Secondary in-page/sub navigation (javascript/sub-nav.js) is used on pages
    with several sections (e.g. neXos-computer.html) for smooth-scroll jumps.

LINKS
  - Internal navigation between all 12 pages uses relative paths.
  - Anchor-based smooth scrolling is used for in-page section links
    (e.g. FAQ, feature jump links) via CSS scroll-smooth / JS scroll handlers.

IMAGES
  - Meaningful alt text is used on descriptive product/feature images
    (e.g. alt="NexOS Pro Laptop", alt="Monitor Display").
  - Images are organised into per-page subfolders under images/
    (main-shop/, keyboard-shop/, tech-page/, nexos-pro-helix/, payment-qr/, etc).
  - Every graphic file is kept under 800KB as required.
  - A 100-frame WebP image sequence (images/images-keyboard-final/) is used to
    drive the canvas scroll animation on keyboard-intro.html.

SPECIAL ELEMENTS
  - Two HTML <table> elements on html/neXos/nexos-shop.html for spec/feature
    comparisons.
  - <select> dropdowns used for hardware selection (nexos-shop.html) and
    payment method choice (payment.html).
  - Checkbox input used for newsletter/consent opt-ins (index.html,
    nexos-shop.html).
  - <audio> playback triggered via JS for keyboard switch sound samples.
  - Embedded/dynamically inserted Google Map on keyboard-shop.html.
  - Custom favicon using images/neXuslogo2.png.
  - Google Fonts (Oxanium, Roboto) loaded via <link> with preconnect for
    performance, plus Font Awesome 4.7.0 for icons.
  - lang="en" attribute set on every page's <html> element.

FORMS / INTERACTIVE ELEMENTS (JavaScript-driven)
  - index.html            - newsletter signup form, HTML5 "required"/type="email"
                             validation, success confirmation modal.
  - html/neXos/nexos-shop.html - multi-step ISO download form: hardware select
                             (required), email (required, type="email"), consent
                             checkbox (required), step-by-step reveal.
  - html/neXus-60HE/keyboard-shop.html - booking form with required date/contact
                             fields and date-range limits.
  - html/payment.html      - checkout form with live JavaScript validation as the
                             user types: card number formatting + length check,
                             expiry date format check (regex), cardholder-name
                             check (regex), all with inline error messages
                             instead of alert().
  - html/find-your-product.html - 4-step interactive quiz built entirely with
                             JS-driven DOM updates (no form submission needed).

COMMENTS
  - HTML files contain comments marking page authorship (e.g.
    "<!-- DONE BY LIANG JUN AND SING SIANG -->") and major section breaks.

VALIDATION
  - Pages have been checked against https://validator.w3.org as required by
    the brief.

CSS / STYLING FEATURES (Relevant to CSS Coding Criteria)
--------------------------------------------------------------------------------

FRAMEWORK
  - Tailwind CSS (loaded via CDN script) is the single styling framework used
    across all 12 pages, providing the utility classes for layout, spacing,
    colour, typography and responsiveness.
  - A small set of hand-written external stylesheets (css/style.css and
    css/nexos-pro.css) supplements Tailwind for effects Tailwind's utility
    classes cannot express on their own (custom keyframe animations, 3D
    transforms, clip-path reveals, GPU-compositing hints).

CSS VARIABLES
  - Defined in :root in css/style.css: --background, --background2, --text,
    --maingreen, --hovergreen, --shop-item.
  - Defined in :root in css/nexos-pro.css: --helix-card-width,
    --helix-card-height, --helix-perspective.
  - Used consistently via var() for theming (e.g. the shared green accent
    colour and dark background across every page).

SELECTORS USED
  - Element selectors: body, h1-h3, header
  - Universal reset: * { border, border-radius, padding, margin }
  - Class selectors: .main-button, .reveal-on-scroll, .hamburger-line,
    .helix-card, .story-text, .cta-shockwave, etc.
  - Pseudo-classes: :hover, :active
  - Class-state combinators: .open .line-1 / .line-2 / .line-3 (hamburger
    icon morphs into an "X" based on a parent .open class)

TEXT, FONT AND COLOUR
  - Two Google Fonts loaded: Roboto (body text) and Oxanium (headings/nav).
  - font-family, font-weight and color set through CSS variables and
    Tailwind utility classes together.
  - color-mix() used for the button glow (box-shadow with a translucent
    tint of --maingreen).

BOX MODEL
  - Global reset removes default border/margin/padding via the * selector,
    with Tailwind utilities then re-applying spacing per element.
  - box-shadow used for the glowing call-to-action button and the
    helix-vignette overlay gradient.

LAYOUT
  - Flexbox and CSS Grid are used extensively through Tailwind's flex/grid
    utility classes (e.g. flex, grid, justify-*, items-*) across every page's
    header, cards and form layouts.
  - Responsive breakpoint prefixes (sm:, md:, lg:) are used hundreds of times
    across the site so layouts adapt from mobile portrait through tablet to
    desktop/landscape, e.g. sm: used 121 times and md: used 37 times on
    nexos-intro.html alone.
  - position: fixed/absolute/relative used for the mobile drawer, modals,
    the helix 3D scene and scroll-pinned sections.
  - clip-path: polygon() used for the before/after performance-slider reveal
    effect (.screen-overlay-clip).
  - CSS 3D transform properties (perspective, transform-style: preserve-3d)
    used to build the rotating double-helix card gallery on nexos-pro.html.

ANIMATIONS
  - A ripple/shockwave effect plays outward from call-to-action buttons when
    clicked.
  - Pop-in animation when modals (pop-up windows) open.
  - Content on the quiz/step pages fades and slides in smoothly as it appears.
  - A gentle up-and-down floating animation on nexos-pro.html.
  - The hamburger menu icon smoothly animates into an "X" shape when opened.
 
SMOOTH SCROLLING PERFORMANCE
  - Extra CSS rules are used behind the scenes to keep scrolling animations
    (like the scroll-triggered sections) running smoothly without stuttering,
    with comments explaining why each rule is there.
 
EXTERNAL STYLESHEETS
  - All custom styling is kept in css/style.css (site-wide) and
    css/nexos-pro.css (used only on nexos-pro.html for its extra effects).
    No styling is written directly inside the HTML files.
 
COMMENTS
  - Both stylesheets contain comments explaining why certain rules were added,
    especially the ones used to keep scrolling animations smooth.

JAVASCRIPT FEATURES (Relevant to JS / Interactivity Criteria)
--------------------------------------------------------------------------------

DOM MANIPULATION (beyond alert())
  - Shared header/footer/nav markup is built and inserted into every page at
    runtime (header-footer.js).
  - Shop product cards are generated dynamically from JSON data and
    re-rendered whenever the user searches, sorts or filters
    (main-shop.js + shop-products.json).
  - The chatbot renders new message bubbles into the DOM and keeps a running
    conversation (chatbot.js + bot-data.json).
  - The product quiz swaps question/answer content in place and reveals a
    final recommendation panel (find-your-product.js).
  - Live inline validation messages are inserted/removed next to each payment
    field as the user types (payment.js).

FORM VALIDATION LOGIC
  - Card number: only numbers are kept as the user types, checked for the
    right length, with an inline message showing if it's valid or not.
  - Expiry date: checked that it matches the MM/YY format.
  - Cardholder name: checked that it only contains letters/spaces and is
    long enough to be a real name.
  - Newsletter/ISO/booking forms: required fields and email fields must be
    filled in correctly before the form can be submitted.
 
SAVED DATA
  - The shopping cart is remembered even after leaving the page or closing
    the tab, so items stay in the cart when the user comes back.
  - The chatbot also remembers the conversation history in the same way.
 
DATA-DRIVEN CONTENT
  - Product listings and chatbot replies are stored in separate data files
    rather than being typed directly into the HTML, so they're easy to
    update in one place.
 
REUSABLE COMPONENTS
  - The FAQ accordion, review carousel and before/after slider are each
    built once and reused across multiple pages instead of being rebuilt
    from scratch every time.
 
ADVANCED / EXTRA INTERACTIVITY
  - The site can check the visitor's graphics card and suggest a compatible
    product based on it.
  - The keyboard intro page plays a 100-image sequence as the user scrolls,
    plus a switch-type selector that updates the specs shown and plays a
    matching sound sample.
  - A 3D "double helix" animation rotates a set of game-cover cards on
    nexos-pro.html.
  - Extra animation and smooth-scrolling libraries are used for the
    typewriter hero text, scroll-triggered reveals and smooth scrolling
    behaviour throughout the site.

DESIGN (Relevant to UX / Responsiveness)
--------------------------------------------------------------------------------

CONTRAST
  - Light text (var(--text) / white) on the shared dark background
    (var(--background): #1e1e1e) throughout the site.
  - The green accent colour (var(--maingreen)) is reserved for primary
    buttons, links and focus states so it stands out against the dark theme.

REPETITION
  - Identical header, nav and footer are reused on every page via the shared
    header-footer.js component.
  - The same FAQ accordion, review carousel and performance-slider components
    are reused wherever needed instead of being rebuilt per page.
  - Consistent green/dark colour palette and Oxanium/Roboto type pairing
    across all 12 pages.

ALIGNMENT
  - Tailwind's flex/grid utilities keep hero sections, product cards and
    comparison tables consistently aligned across breakpoints.

PROXIMITY
  - Related form fields (e.g. card number/expiry/CVV) are grouped together
    with their inline validation messages directly beneath them.
  - Product image, price and add-to-cart button are grouped within a single
    card component in the shop pages.

RESPONSIVENESS / USABILITY
  - Mobile hamburger drawer collapses the desktop nav on small screens.
  - Layouts confirmed responsive from mobile portrait through tablet to
    desktop/landscape using Tailwind's sm:/md:/lg: breakpoints (used
    hundreds of times site-wide).
  - Toast notifications and inline modal confirmations give immediate
    feedback for cart and form actions instead of blocking alert() pop-ups.
